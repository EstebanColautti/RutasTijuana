# Trabajo en el repositorio

- Seguir el flujo de CONTRIBUTING.md en cada cambio.
- Crear o reutilizar un issue y trabajar en una rama por tarea, partiendo de main actualizado.
- Mantener los cambios acotados; usar commits, títulos y documentación breves en español.
- No agregar referencias de autoría, sugerencias ni comentarios innecesarios en el código o la documentación.
- No modificar main directamente, forzar pushes a main ni omitir sus protecciones.
- Abrir un PR en borrador, enlazar el issue y describir la validación real.
- Revisar el diff y corregir problemas antes de marcar el PR listo para revisión.
- Esperar las verificaciones del último cambio y resolver todas las conversaciones antes de integrar.
- Integrar con squash cuando la solicitud autorice completar el cambio; dejar el PR listo si solo se pidió prepararlo.
- Eliminar la rama tras la integración y comprobar el estado final de main.
- Publicar etiquetas y releases únicamente para entregas validadas y autorizadas.
- No inventar rutas, horarios, datos estadísticos, resultados de pruebas ni capturas.
